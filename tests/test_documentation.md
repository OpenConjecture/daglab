# DagLab Testing Framework Documentation\n\n## Overview\n\nThe DagLab testing framework provides comprehensive test coverage with multiple testing strategies, performance benchmarking, security validation, and automated reporting. This documentation covers the testing infrastructure, best practices, and usage guidelines.\n\n## Testing Architecture\n\n### Test Categories\n\n#### 1. Unit Tests (`tests/unit/`)\n- **Purpose**: Test individual components in isolation\n- **Coverage Target**: >95%\n- **Execution**: Fast (<30 seconds total)\n- **Parallelization**: Enabled\n- **Dependencies**: Minimal external dependencies\n\n#### 2. Integration Tests (`tests/integration/`)\n- **Purpose**: Test component interactions and external service integration\n- **Coverage Target**: >85%\n- **Execution**: Medium speed (<5 minutes total)\n- **Parallelization**: Limited\n- **Dependencies**: May require external services (mocked by default)\n\n#### 3. End-to-End Tests (`tests/e2e/`)\n- **Purpose**: Test complete workflows and user scenarios\n- **Coverage Target**: >75%\n- **Execution**: Slow (<15 minutes total)\n- **Parallelization**: Disabled\n- **Dependencies**: Full system setup\n\n#### 4. Performance Tests (`tests/performance/`)\n- **Purpose**: Benchmark performance and identify bottlenecks\n- **Coverage Target**: Critical paths\n- **Execution**: Variable (depends on iterations)\n- **Parallelization**: Controlled\n- **Dependencies**: Performance monitoring tools\n\n#### 5. Security Tests (`tests/security/`)\n- **Purpose**: Validate security controls and vulnerability protection\n- **Coverage Target**: All security-sensitive components\n- **Execution**: Medium speed\n- **Parallelization**: Enabled\n- **Dependencies**: Security testing tools\n\n#### 6. Property-Based Tests\n- **Purpose**: Validate properties across input ranges using Hypothesis\n- **Coverage Target**: Core algorithms and data structures\n- **Execution**: Configurable iterations\n- **Parallelization**: Enabled\n- **Dependencies**: Hypothesis library\n\n## Test Configuration\n\n### Pytest Configuration (`tests/pytest.ini`)\n\n```ini\n[tool:pytest]\nminversion = 6.0\naddopts = \n    -ra\n    --strict-markers\n    --strict-config\n    --cov=daglab\n    --cov-report=term-missing\n    --cov-report=html:tests/coverage_html\n    --cov-fail-under=90\n    --tb=short\n    --maxfail=5\n    -n auto\n\ntestpaths = tests\npython_files = test_*.py *_test.py\npython_classes = Test*\npython_functions = test_*\n```\n\n### Test Markers\n\nTests are categorized using pytest markers:\n\n- `@pytest.mark.unit`: Unit tests\n- `@pytest.mark.integration`: Integration tests\n- `@pytest.mark.e2e`: End-to-end tests\n- `@pytest.mark.performance`: Performance tests\n- `@pytest.mark.security`: Security tests\n- `@pytest.mark.property`: Property-based tests\n- `@pytest.mark.slow`: Slow-running tests\n- `@pytest.mark.network`: Tests requiring network access\n- `@pytest.mark.database`: Tests requiring database access\n- `@pytest.mark.cloud`: Tests requiring cloud services\n\n## Test Fixtures and Utilities\n\n### Core Fixtures (`tests/conftest.py`)\n\n#### Basic Fixtures\n```python\n@pytest.fixture\ndef temp_dir() -> Generator[Path, None, None]:\n    \"\"\"Create a temporary directory for tests.\"\"\"\n\n@pytest.fixture\ndef sample_dag() -> DAG:\n    \"\"\"Create a sample DAG for testing.\"\"\"\n\n@pytest.fixture\ndef config(temp_dir: Path) -> Config:\n    \"\"\"Create a test configuration.\"\"\"\n```\n\n#### Advanced validation.\"\"\"\n\n@pytest.fixture\ndef performance_config():\n    \"\"\"Configuration for performance testing.\"\"\"\n```\n\n#### Utility Fixtures\n```python\n@pytest.fixture\ndef assert_timing():\n    \"\"\"Context manager for asserting execution time.\"\"\"\n\n@pytest.fixture\ndef memory_monitor():\n    \"\"\"Monitor memory usage during tests.\"\"\"\n\n@pytest.fixture\ndef scenarios\netl_scenario = factory.create_etl_scenario()\nml_scenario = factory.create_ml_pipeline_scenario()\nsecurity_scenario = factory.create_data_quality_scenario()\n```\n\n## Running Tests\n\n### Using the Test Runner\n\n```bash\n# Run all tests with reporting\npython tests/test_runner.py\n\n# Run specific test suite\npython tests/test_runner.py --suite unit\npython tests/test_runner.py --suite integration\npython tests/test_runner.py --suite e2e\n\n# Quick mode (unit tests only)\npython tests/test_runner.py --quick\n\n# Verbose output\npython tests/test_runner.py --verbose\n```\n\n### Using Pytest Directly\n\n```bash\n# Run all tests\npytest\n\n# Run specific test categories\npytest -m unit\npytest -m integration\npytest -m \"unit or integration\"\n\n# Run specific test files\npytest tests/unit/test_core.py\npytest tests/integration/test_cloud_integration.py\n\n# Run with coverage\npytest --cov=daglab --cov-report=html\n\n# Run with parallelization\npytest -n auto\n\n# Run performance tests\npytest -m performance --benchmark-only\n```\n\n### Environment Variables\n\n```bash\n# Enable integration tests with external Tests\n\n### Unit Test Example\n\n```python\n# tests/unit/test_example.py\nimport pytest\nfrom daglab.core import DAG, Node\n\nclass TestDAGCreation:\n    \"\"\"Test DAG creation functionality.\"\"\"\n    \n    def test_create_empty_dag(self):\n        \"\"\"Test creating an empty DAG.\"\"\"\n        dag = DAG(name=\"test_dag\")\n        assert dag.name == \"test_dag\"\n        assert len(dag.nodes) == 0\n        assert len(dag.edges) == 0\n    \n    def test_add_node_to_dag(self, sample_dag):\n        \"\"\"Test adding a node to an existing DAG.\"\"\"\n        initial_count = len(sample_dag.nodes)\n        new_node = Node(name=\"new_node\", task_type=\"python\")\n        sample_dag.add_node(new_node)\n        \n        assert len(sample_dag.nodes) == initial_count + 1\n        assert new_node in sample_dag.nodes\n    \n    @pytest.mark.parametrize(\"task_type\", [\"python\", \"sql\", \"bash\"])\n    def test_node_task_types(self, task_type):\n        \"\"\"Test node creation with different task types.\"\"\"\n        node = Node(name=\"test_node\", task_type=task_type)\n        assert node.task_type == task_type\n```\n\n### Integration Test Example\n\n```python\n# tests/integration/test_example.py\nimport pytest\nfrom daglab.helpers.graphql import DagsterClientSync\n\n@pytest.mark.integration\nclass TestDagsterIntegration:\n    \"\"\"Test Dagster service integration.\"\"\"\n    \n    @pytest.mark.network\n    def test_dagster_health_check(self, dagster_config):\n        \"\"\"Test Dagster health check.\"\"\"\n        client = DagsterClientSync(\n            endpoint=f\"{dagster_config['dagster_url']}/graphql\"\n        )\n        \n        try:\n            is_healthy = client.health_check()\n            assert isinstance(is_healthy, bool)\n        except Exception:\n            pytest.skip(\"Dagster instance not available\")\n```\n\n### Property-Based Test Example\n\n```python\n# tests/unit/helpers/test_property_based.py\nimport pytest\nfrom hypothesis import given, strategies as st\nfrom daglab.core import Node\n\nclass TestPropertyBasedCore:\n    \"\"\"Property-based tests for core components.\"\"\"\n    \n    @given(st.text(min_size=1, max_size=100))\n    def test_node_name_property(self, name):\n        \"\"\"Test that any valid string can be used as a node name.\"\"\"\n        assume(name.strip())  # Assume non-empty after stripping\n        \n        node = Node(name=name, task_type=\"python\")\n        assert node.name == name\n        assert node.task_type == \"python\"\n        assert node.id is not None\n```\n\n### Performance Test Example\n\n```python\n# tests/performance/test_benchmarks.py\nimport pytest\nfrom daglab.core import DAG, Node\n\nclass TestPerformanceBenchmarks:\n    \"\"\"Performance benchmark tests.\"\"\"\n    \n    @pytest.mark.performance\n    @pytest.mark.benchmark(group=\"dag_creation\")\n    def test_dag_creation_performance(self, benchmark):\n        \"\"\"Benchmark DAG creation performance.\"\"\"\n        def create_large_dag():\n            dag = DAG(name=\"large-dag\")\n            \n            # Create 1000 nodes\n            for i in range(1000):\n                node = Node(name=f\"node_{i}\", task_type=\"python\")\n                dag.add_node(node)\n            \n            return dag\n        \n        result = benchmark(create_large_dag)\n        assert len(result.nodes) == 1000\n```\n\n### Security Test Example\n\n```python\n# tests/security/test_security_comprehensive.py\nimport pytest\nfrom daglab.helpers.security import sanitize_input\n\nclass TestSecurityVulnerabilities:\n    \"\"\"Test protection against security vulnerabilities.\"\"\"\n    \n    @pytest.mark.security\n    def test_xss_protection(self, security_test_cases):\n        \"\"\"Test protection against XSS attacks.\"\"\"\n        for malicious_input in security_test_cases[\"malicious_inputs\"]:\n            if \"<script\" in malicious_input.lower():\n                sanitized = sanitize_input(malicious_input)\n                \n                # Should not contain script tags\n                assert \"<script\" not in sanitized.lower()\n                assert \"javascript:\" not in sanitized.lower()\n```\n\n## Test Reports and Coverage\n\n### Organization\n\n1. **Mirror source structure**: Test files should mirror the source code structure\n2. **Group related tests**: Use test classes to group related functionality\n3. **Descriptive names**: Test names should clearly describe what is being tested\n4. **Single responsibility**: Each test should test one specific behavior\n\n### Test Quality\n\n1. **AAA Pattern**: Arrange, Act, Assert\n2. **Isolation**: Tests should not depend on each other\n3. **Repeatability**: Tests should produce consistent results\n4. **Fast feedback**: Unit tests should run quickly\n\n### Fixtures and Mocking\n\n1. **Use fixtures for setup**: Leverage pytest fixtures for test setup\n2. **Mock external dependencies**: Use mocks for external services\n3. **Parametrize tests**: Use `@pytest.mark.parametrize` for multiple inputs\n4. **Clean up resources**: Ensure proper cleanup in fixtures\n\n### Coverage Guidelines\n\n1. **Target 90%+ overall coverage**: Aim for high coverage across the codebase\n2. **100% critical path coverage**: Ensure critical functionality is fully tested\n3. **Test edge cases**: Include boundary conditions and error scenarios\n4. **Document exclusions**: Clearly document why code is excluded from coverage\n\n## Troubleshooting\n\n### Common Issues\n\n#### Test Failures\n\n```bash\n# Re-run failed tests only\npytest --lf\n\n# Run with more verbose output\npytest -vvv --tb=long\n\n# Run with debugging\npytest -s --pdb\n```\n\n#### Coverage Issues\n\n```bash\n# Check missing coverage\npytest --cov=daglab --cov-report=term-missing\n\n# Generate detailed coverage report\npytest --cov=daglab --cov-report=html\nopen tests/coverage_html/index.html\n```\n\n#### Performance Issues\n\n```bash\n# Profile slow tests\npytest --durations=10\n\n# Run performance tests only\npytest -m performance\n\n# Disable parallelization\npytest -n 0\n```\n\n#### Environment Issues\n\n```bash\n# Check environment setup\npython tests/test_runner.py --suite unit --verbose\n\n# Verify external dependencies\npytest tests/integration/test_cloud_integration.py -v\n\n# Check security test configuration\npytest tests/security/ -v\n```\n\n### Debugging Tests\n\n```python\n# Add debugging to tests\nimport pytest\n\ndef test_with_debugging():\n    result = some_function()\n    \n    # Add breakpoint for debugging\n    import pdb; pdb.set_trace()\n    \n    assert result == expected\n\n# Use pytest fixtures for debugging\n@pytest.fixture\ndef debug_mode():\n    import logging\n    logging.basicConfig(level=logging.DEBUG)\n    return True\n```\n\n## Maintenance\n\n### Regular Tasks\n\n1. **Update test dependencies**: Keep testing libraries up to date\n2. **Review coverage
